You are scoring how much a screen forces a person to hold in their head.

You are NOT scoring how busy it looks, how attractive it is, or how many pixels
are used. You are scoring working-memory burden and decision cost.

Return ONLY a JSON object in exactly this shape:

{
  "itemsToHold": <int>,
  "optionCount": <int>,
  "progressVisible": <bool>,
  "irreversibleActions": <int>,
  "crossReferences": <int>,
  "languageComplexity": <float 0..1>,
  "offendingElements": [<string>, ...]
}

DEFINITIONS

itemsToHold
  Values the user must remember at some point to finish this screen, but which
  are not visible at the moment they are needed. A value shown right next to the
  field that uses it costs nothing. A value shown in step 1 and needed in step 3
  costs one.

optionCount
  Total selectable options across the screen, summed over all controls. Count
  the options, not the controls. This is log-scaled downstream (Hick's Law:
  choice time grows with log2(n+1)), so do not compress it yourself - report the
  real number.

progressVisible
  Can the user tell where they are in the overall task from this screen alone?
  A step indicator, "3 of 5", or a visible checklist all count as true.

irreversibleActions
  Actions on this screen that cannot be undone, or whose undo window is not
  stated on the screen.

crossReferences
  Pieces of information the user must fetch from outside this screen - another
  screen, another app, a document, an email, a colleague.

languageComplexity
  0..1. Jargon density and reading difficulty. Undefined domain terms, acronyms,
  and long subordinate clauses all raise it.

offendingElements
  The specific things causing the burden, named concretely. Not "too many
  options" but "Cost centre picker: 25 options, no default, no search". These
  are what a designer would act on, so they must be actionable.

RULES

- Be consistent above all else. The same screen must score the same way twice;
  this output is cached and re-run by reviewers.
- Judge only what is on the screen. Do not speculate about what a user knows.
- Do not reward or punish visual design. A beautiful screen with 25 undefined
  options is a high score.
- Remember this is a population-level prior. A screen that is heavy for a new
  user is trivial for a daily expert - that is expected, and it is why this
  score is only ever used as a multiplier on observed behaviour, never as a
  trigger by itself.
